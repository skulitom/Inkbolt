# B15: Repair missing and corrupt resources (prompt version 1)

source.json is a 16 by 8 vector document containing two 8 by 8 image objects,
side by side. Their pinned 2 by 2 resources are bound to broken-assets: asset-0
has a deliberately corrupt cache file, and asset-1 has no cache file. Diagnose
both at their exact resource locations, recreate the exact resources from
original-0.png and original-1.png in a new repaired-assets directory, review the
binding change, and commit only that change. Do not edit the source document,
artwork, original images, corrupt file, or historical resource bindings. Leave
the missing file missing in broken-assets.

Keep all document fields, item IDs, geometry, transforms and asset descriptors.
Save editable.json, bindings.json and a 16 by 8 preview.png: opaque blue
(20,80,150,255) on the left eight columns and green (30,150,70,255) on the right.
bindings.json must contain exactly:

```json
{"before":"broken-assets","after":"repaired-assets"}
```

Retain diagnostics.json with exactly the complete initial diagnosis below,
derived from inspecting the actual broken cache:

```json
{"status":"fail","issues":[{"code":"ASSET_CORRUPT","pointer":"/assets/asset-0"},{"code":"ASSET_MISSING","pointer":"/assets/asset-1"}]}
```

With Inkbolt, create a session from source.json bound to broken-assets. Import
both original PNGs into repaired-assets; retain before.json from the initial
revision. Use session.dry_run and session.apply_proposal for one resource-binding
action, retaining the full dry-run result in review.json. Save the repaired
revision as editable.json, review its preview, verify session history and check
that the old revision still diagnoses both broken resources. Choose your own
session and request IDs. Retain session.json with exactly `session_id`,
`before_revision` (0), `after_revision` (the repaired current revision),
`creation` (creation request ID), `repair` (repair request ID), and
`workspace_root` (your original absolute workspace path). The judge compares
retained review states with durable creation/repair receipts and checks fresh
artifacts independently of the solver transcript.

For the no-engine baseline, keep editable.json logically identical to source.json
and within 16 KiB, with bindings.json as the separate editable resource recipe.
Use pinned Python/Pillow to decode the originals and write the exact cache files.
Each cache consists of the eight ASCII bytes INKRGBA1, two little-endian u32
dimensions (2,2), and sixteen straight RGBA8 bytes in row order. Its filename is
the SHA-256 of all 32 bytes followed by .rgba8. Both filenames and hashes must
match the original asset descriptors. The original PNGs are each bounded to
4 KiB. Render the preview from this editable arrangement and repaired cache;
do not flatten the source into a replacement document. Numerical/file processing
is allowed, and Inkbolt is unavailable.

The four artifact checks are the same across both arms. Only Inkbolt historical
binding and session-integrity checks are not applicable to the baseline. The old
cache remains preserved in both arms. Imported trials are checked using captured
resource copies. Stored absolute roots are compared as retained binding data;
the judge does not follow stale roots or silently rewrite historical sessions.
Retained proposals and hashes establish consistent content, not authenticated
attestation that a client actually reviewed it.
