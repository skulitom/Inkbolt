# B16: Diagnose and repair text overflow (prompt version 2)

Build a 48 by 32 vector canvas with an AA text frame at the origin, using
original.ttf and font-license.txt. Its style is size 20, solid RGBA (20,80,150,255),
left aligned, left-to-right, no tracking, no wrapping and overflow treated as an
error. Initially the frame is 12 wide and 24 high. Include an unrelated solid
green (30,150,70,255) rectangle at (32,20), size 8 by 8. Keep ordinary document
defaults, with no extra content, effects, transforms or output profiles.

Diagnose the overflow and its exact location. Change only the frame width to 24
through a reviewed repair. Preserve both letters, the exact original font and
license, and all unrelated controls and artwork. Retain before.json and
editable.json, a 48 by 32 review.png and the create-only final repaired.png.
Review and preflight the repaired result before publication. Its two blue glyph
rectangles occupy (1,2,8,14) and (13,2,8,14), the green rectangle is unchanged,
and all other pixels are transparent black.

Retain diagnostics.json with exactly this initial actionable diagnosis. The
suggested width follows from the original font's two 600-unit advances at size
20 and 1000 units per em; clipping text is not a repair.

```json
{"status":"fail","ready":false,"code":"TEXT_OVERFLOW","pointer":"/items/0/content","suggested_width":24}
```

Retain delivery.json with exactly `file` (repaired.png), `ready` (true),
`preflight_sha256` (prepared PNG bytes) and `sha256` (final PNG bytes). Both hashes
must match. Keep the originals unchanged.

With Inkbolt, import the original font/license into the default workspace store.
Choose your own document, item, font, session and request IDs. Save the initial
revision (0), inspect document.check and the failed document.preflight, and use
session.dry_run with a preview followed by session.apply_proposal for a single
text operation changing only width. Save its full dry-run result as review.json
and its image as review.png. Keep the default empty edit label. Preflight and
session.publish the repaired revision (1), using a durable publication receipt;
verify history. Retain session.json with exactly `session_id`, `before_revision`
(0), `after_revision` (1), `creation`, `repair` and `publication` request IDs.
The independent judge reopens sources, diagnostics, preflight, previews and
durable receipts; it does not use the solver's command results as its verdict.
In this arm, before.json and editable.json must be editable Inkbolt documents
that reopen as saved revisions 0 and 1 respectively and agree with those saved
states. Ordinary default fields may be omitted when they reopen equivalently;
an omitted revision reopens as 0. Retain the committed source, including its
revision, when delivering editable.json.

For the no-engine baseline, retain the same explicit editable recipe in
before.json and editable.json, with schema_version 2, id repair, kind vector,
width 48, height 32, color_space srgb, fonts and items. Use font ID face and item
IDs label and other. The font descriptor has original-file sha256,
license_sha256, face_index 0 and bytes. Each item contains only id and content;
text content has type text and frame with text, width, height, wrap and style
(font_id, size, fill). Rectangle content has type vector, geometry (shape rect,
x, y, width, height) and fill. Only the frame width changes; omit implicit
defaults from both recipes. Keep each recipe and SVG within 16 KiB.
In these baseline recipes, fonts is an object keyed by face, whose value is the
font descriptor. Its bytes field is the integer byte length of original.ttf.
Set wrap to the JSON boolean false. Both fill fields are bare four-integer RGBA
arrays: [20,80,150,255] for text and [30,150,70,255] for the rectangle. Keep these
field types in both recipes. Baseline recipes omit revision; Inkbolt's saved
revision requirement above applies only to the Inkbolt arm.

Also retain before.svg and editable.svg. Each is an SVG canvas containing one
nested SVG frame (id label, x/y 0, height 24, initial width 12 or repaired 24),
one editable AA text node (x 0, baseline y 16, size 20, font-family Inkbolt Repair
Fixture, blue fill), and the unrelated green rect (id other). Optional matching
viewBox and root version are allowed. No other nodes, attributes, resources,
styles or transforms are admitted. renderer.ttf adds only family naming to the
original geometric font; use it with pinned resvg and disabled system fonts.
Measure the original font, diagnose the initial overflow, prepare and inspect
the repaired image with pinned Python/Pillow, then publish the exact prepared
bytes without overwriting any output. Inkbolt is unavailable to this arm.

All four artifact checks apply to both arms. Only Inkbolt durable history is
not applicable to the baseline. Recorded reports and hashes establish consistent
content, not authenticated proof of a client's historical review actions.
Relocated Inkbolt captures use their captured font files for fresh evaluation;
historical resource roots remain unchanged and are never followed by the judge.
