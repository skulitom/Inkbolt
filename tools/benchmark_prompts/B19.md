# B19: Cancel, interrupt and recover output (prompt version 2)

For an external run, invoke the exact argv array in request.json's recovery_bridge
field with one JSON message on stdin. It returns one JSON engine envelope on
stdout and exits 0 for success or 1 for an error. Use a unique portable step name
(letters, digits, dot, underscore or hyphen, at most 120 characters) per message.
Send one message at a time. Ordinary messages have this form:

```json
{"step":"image","command":"asset.import","arguments":{"source_path":"original.png"}}
```

Use expected_error for the known JOB_NOT_COMPLETED and OUTPUT_EXISTS refusals.
Use retry_of with the earlier step name for each exact request replay. These are
benchmark annotations, outside arguments. Keep the original request fields on
retries. All Inkbolt calls must use this bridge; direct engine/MCP calls would
escape the required owned-process observations. Do not inspect harness evidence,
control-channel files or process IDs directly. The bridge uses local files and
has no network listener. The reference workflow uses the same engine and owned
fault controls directly.

Import original.png, an original 1024 by 1024 texture. Create session work at
revision 0 using request ID create. Use document ID recovery, vector kind, sRGB
and 96 ppi. Store the imported asset under key photo, with object IDs image and
badge in that order; leave other properties at their defaults. Place the image
at its original size and a green (30,150,70,255) badge
at (32,40), size 24 by 20. Keep the image editable and unchanged. Save a focused
badge preview as preview.png (24 by 20 pixels).

Use the harness's owned-process controls for both faults. Cancel request cancel,
writing cancelled.png, after rendering starts. It must remain cancelled when
resumed and have no result or output. Queue request recover for revision 0,
writing recovered.png, while the harness holds its queue gate. Change only the
current badge fill to orange (220,90,30,255), request ID newer, expected revision
0. Then release the gate and let the harness interrupt the exact supervisor while
rendering. Neither you nor the harness may edit engine databases or target
unrelated processes. No engine pause hook is used.

For external runs, send these three control messages in order:

- control cancel-active, arguments containing document (the saved revision 0
  reference) and output {"file_name":"cancelled.png","format":"png"}. The
  harness starts the job and cancels it during observed rendering. Then use
  ordinary wait/resume/result calls to inspect its terminal outcome.
- control hold-queue, arguments {}. Then submit ordinary job.start for recover
  using saved revision 0 and recovered.png, followed by the newer edit. The queue
  stays held while you issue those commands.
- control interrupt-queued, arguments {}. The harness releases its queue gate,
  resumes recover and interrupts its exact supervisor during rendering. Then
  continue the ordinary inspection/recovery steps below.

Each control message also needs a unique step. For example:
{"step":"gate","control":"hold-queue","arguments":{}}.
The harness captures the interrupted inspection after the expected failed
job.result, the first completed receipt, and the overwrite refusal automatically.

Inspect the interrupted job with status, zero-duration wait and result. Inspection
must not publish or restart it. Explicitly resume, wait for completion and recover
the pinned green image from revision 0. Save current revision 1 as editable.json.
Retry the original recover submission, resume the completed job and fetch its
result again. They must preserve one receipt, attempt 2 and the same physical
file. Try publishing revision 1 to recovered.png; require OUTPUT_EXISTS. Verify
session history. Preserve original.png and all existing outputs.

Retain attempts.json containing the actual full returned objects under these
keys: cancelled, cancel-resume, cancel-error, interrupted-status,
interrupted-wait, interrupted-error, completed, receipt, start-replay,
resume-completed, result-replay and overwrite-error. Error entries contain the
error object. Other entries contain the command's result object.

The independent judge reopens original/current artwork and durable receipts,
renders fresh previews, checks every delivered pixel, and checks the harness's
observed fault boundaries, process identities and output identities. All eight
original checks remain fixed. File polling does not observe every instant and
hashes do not authenticate historical client behavior. The no-engine baseline is
not applicable to Inkbolt job recovery. Windows containment is required; Unix
jobs are still unsupported. The harness measures engine calls, traffic, retries,
first verified preview availability and process peaks separately from client
usage. Missing model/token usage remains unknown. Captured trials retain this
evidence and rejudge without reinjecting faults. Synthetic references/clients
are not model trials.
