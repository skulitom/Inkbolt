# B07: Produce multilingual typography (prompt version 1)

Create a 1000 by 960 transparent typography sheet from the four exact logical
strings in `texts.json`. Preserve that file, `original.ttf`, `font-license.txt`
and this prompt. Use only the supplied original geometric font, blue RGBA
(20,80,150,255), size 200, Unicode bidirectional ordering with automatic base
direction and no wrapping. Place the four rows at x=0, y=0/240/480/720 in 1000
by 240 text frames. Baselines are at y=200/440/680/920 on the sheet. Keep the
logical Unicode source and separately editable text; do not reorder stored
characters, substitute installed fonts, flatten text or convert it to paths.

Inspect Hebrew and Arabic visual order, Arabic joining, combining-mark anchors,
Indic prebase order, Han glyphs and the fi ligature. The supplied font has family
`Inkbolt Typography Fixture`, 1000 units per em and ascent 1000. Its glyphs are
distinct numbered geometric shapes, not normal letterforms. Inspect its original
OpenType metrics, cmap, substitution and positioning tables when needed.

Deliver and review `preview.png`, the complete 1000 by 960 transparent RGBA
image. Use new output files without overwriting existing files. Deliver
`shaping.json` with exactly these fields:

- `indices`: `unicode_scalars`
- `glyph_clusters`: `logical_scalar_intervals`
- `rows`: four objects in source order, each with exactly `text` and `glyphs`.

Each `text` is the exact original logical string. List glyphs in visual order.
Each glyph entry is `[glyph_id, start, end, [x, y], advance]`. Glyph IDs and
half-open logical source offsets are integers; offsets count Unicode scalars
within that row. Origins and advances are in local frame pixels, with y increasing
downward from the frame top. Include spaces, zero-advance marks and ligatures.
Keep shared logical intervals for glyphs in the same cluster. This is a delivered
source-to-glyph mapping; the judge checks it against independent authored metrics,
source intervals and visible glyph geometry. Do not claim it is a renderer's
internal observation unless your tool actually provides that observation.

With Inkbolt, import the font/license, create and save the document, inspect each
text row and publish the final snapshot as `editable.json`. Use the actual
inspection results for the shaping report, and verify history. You choose
document, object, font binding, session and request IDs. The delivered snapshot
must match the session's current revision. Deliver `session.json` with exactly
`session_id` and `current_revision`, using your actual values.

For the no-engine baseline, deliver `editable.svg`, `preview.png` and the same
shaping report. Use a UTF-8 SVG at most 64 KiB, the SVG namespace, numeric 1000
by 960 dimensions and an optional matching viewBox. Its only children are four
`text` elements in source order, with numeric x=0 and the sheet baselines given
above. Each uses `font-family="Inkbolt Typography Fixture"`, numeric font-size
200 and #145096 or numeric rgb(20,80,150) fill. Optional row IDs must be unique.
Optional direction is ltr, matching the first strong character of every row.

You may use up to 16 flat `tspan` children per row to preserve editable script
runs. A span may have one numeric `x` coordinate from 0 to 1000. The concatenated
text and span tails must equal the original logical string exactly. Text and
spans may use `xml:space="default"` or `xml:space="preserve"`. No other elements,
attributes, stylesheets, transforms, document types or resources are admitted.
The judge independently renders with the pinned tool, system fonts disabled
and only the supplied font, then checks every visible glyph pixel and the
declared logical mapping. This does not expose the renderer's internal cluster
data. The two engine-only snapshot/history checks are not applicable in this arm.
