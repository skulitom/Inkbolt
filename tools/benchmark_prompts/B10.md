# B10: Edit a multi-megapixel photograph (prompt version 1)

Open `original.png`, an original synthetic studio photograph, 1920 by 1080,
16-bit RGBA in encoded sRGB with straight alpha. Preserve this file and prompt.
Repair only the rectangle (1150,766,12,14), in zero-based pixel coordinates, by
copying the same-layer original rectangle 96 pixels left. Copy every native
16-bit channel exactly, including alpha. Keep all other samples unchanged; do
not rescale, quantize to 8-bit, flatten precision, or alter color interpretation.

Deliver `edited.tiff`: full-size, single-image, uncompressed, interleaved RGBA16
TIFF, unsigned channels, RGB photometric interpretation, straight alpha, top-left
orientation. Retain an editable native layer. Deliver and review `preview.png`,
the exact 12 by 14 repaired region in RGBA8. Map each 16-bit channel to 8-bit by
rounding to nearest (`(value * 255 + 32767) // 65535`). Use new output files.

With Inkbolt, import native tiled storage with `sample.import`, `storage:{}`
and `color_policy:"assume_srgb"`. Choose your own document/session/request IDs;
retain the imported layer `pixels` and all other default document properties.
Save the original as session revision 0. Review one clone repair using
`session.dry_run` with `include_document:true`, then commit that same proposal.
Deliver the exact import result as `import-report.json` and dry-run result as
`review.json`. Keep immutable base tiles. Use tiled evaluation for preview/TIFF.

Deliver `before.json` (original revision 0), `edited.json` (reviewed edit,
revision 1), and `historical.tiff` from the original saved revision. Undo once
and deliver `undo-source.json` (revision 2), then redo once and deliver
`editable.json` (revision 3, matching the final session head). Verify history.
Snapshots and every native TIFF sample are independently checked. Deliver
`publication-report.json` with exactly `edited` and `historical` entries containing
the unchanged TIFF publication results, including their hashes. Deliver
`session.json` with exactly this shape, using your actual chosen IDs:

```json
{"session_id":"your-session","requests":{"create":"your-create-request","edit":"your-reviewed-edit-request","undo":"your-undo-request","redo":"your-redo-request"}}
```

For the no-engine baseline, use the supplied pinned Python/Pillow environment
and ordinary file/shell tools. Retain the native edited layer in `edited.tiff`
and deliver `editable.json` with exactly this manifest:

```json
{"width":1920,"height":1080,"image":"edited.tiff","depth":"u16","channels":"rgba","encoding":"encoded_srgb","transform":[1,0,0,1,0,0]}
```

Ordinary multichannel Pillow conversion can lose 16-bit precision. You may use
Python standard-library byte/array processing or separate native-depth channel
images to retain exact samples, then use Pillow for the focused PNG. The judge
checks every TIFF sample independently of Pillow's display conversion and
reopens the image using the pinned tool. Import/proposal, saved-revision,
undo/redo, immutable engine tiles and session integrity are separate engine-only
checks, not applicable in the baseline.

The unchanged memory budget is at most 256 MiB peak committed memory per
engine/tool process across import, review, repair and delivery. External runs
must spawn local work under the configured client, without offloading to a
pre-existing worker. On Windows, the harness observes the largest process peak
in the whole owned tree, including the launcher and client. A value at or below
256 MiB establishes a conservative bound; a larger or unavailable observation
does not establish this requirement. It is not relabelled as engine-only usage.
Client-written memory claims are ignored/rejected. Linux commit measurement is
currently unavailable; that budget check fails explicitly while other checks
remain visible. Preserve failures; do not replace this metric with resident memory.
