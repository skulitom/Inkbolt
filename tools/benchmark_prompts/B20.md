# B20: Revise a linked animated graphic (prompt version 2)

For an external run, invoke the exact handoff_bridge argv array from request.json
with one JSON message on stdin. The response is a JSON engine envelope on stdout,
with exit 0 for success and 1 for an error. Send messages sequentially, with a
unique portable step label per engine (letters/digits/dot/underscore/hyphen,
at most 120 characters). Choose your own labels. For example:

```json
{"engine":"consumer","step":"discover","command":"capabilities","arguments":{}}
```

engine is inkbolt or consumer. Use command capabilities or schema to discover
the public interfaces. Put command fields inside arguments. expected_error and
retry_of are optional message-level annotations; annotate the required known
refusal and the exact receipt retry. All Inkbolt/Cutbolt commands must use this
bridge, which retains actual process/traffic observations. Do not inspect harness
evidence or control-channel files directly. This is a local file channel, with
no network listener. Preparation launches no engine. The following model/reference
workflow is followed by the baseline-specific file contract.

original.rgba contains two consecutive 32 by 16, row-major, straight RGBA8 frames
in encoded sRGB, 2048 bytes each. Preserve those bytes. Create raster document
linked-graphic in session work using request create, with editable layers art and other,
in that order. Use the sequence frame IDs/datasets frame-0 and frame-1, visibility
bindings layer-0 and layer-1, and select frame-0. Hold the first frame for 3/25
second and the second for 2/25 second, with source plays 0. Leave other document
and item properties at their defaults.

Export revision 0 into delivery-0 with link key graphic, sequence selection,
strict timing, a 2/5-second duration, 25 fps and transparent alpha, looping the
two frames twice. Retain the returned handoff as delivery-0-handoff.json. Inspect
it and compile its scene with the supplied Cutbolt tool to delivery-0/compiled.mkv.
The compiled asset is graphic-r0 with the relative path delivery-0/compiled.mkv.

Create saved Cutbolt project linked in cutbolt-store, 32 by 16 at 25 fps. At
revision 1, request initial, give its enabled, unlocked alpha-over video track
overlay two consecutive 2/5-second clips: graphic at zero and unrelated at 2/5,
both using graphic-r0 from source zero. The timeline duration is 4/5 second.

Review and commit only a four-pixel horizontal translation of art in Inkbolt,
using request move against revision 0. Preserve the second frame, timing, alpha,
color, all other controls and history. Save review.json, before.json, after.json,
historical-source.json and the revised 32 by 16 preview.png. Export revision 1
into delivery-1, explicitly pinning the old handoff as its predecessor. Retain
delivery-1-handoff.json and compile delivery-1/compiled.mkv as asset graphic-r1,
again using its relative path.

The export must not update the saved timeline. Explicitly preview a replacement
against consumer revision 1: add graphic-r1, remove only clip graphic with
reject_partial links, and place graphic at the same time, source and duration
with collision reject. Commit request relink. Preserve unrelated and every old
revision. Attempt a different request stale against revision 1 and retain its
REVISION_CONFLICT error. Undo request undo against revision 2, then repeat the
exact relink request and retain its original receipt without reapplying it.

Retain the actual consumer snapshots as timeline-before.json, before-relink.json,
after-review.json, timeline-after.json, historical.json, restored.json and
after-retry.json. Retain consumer-attempts.json with the actual returned results
for initial, review, relink, stale, undo and retry (stale contains its error
object). Render the original, revised and undone timeline snapshots to
original.mkv, revised.mkv and undone.mkv. Inspect the old handoff and verify
Inkbolt history. Preserve all original delivery files and compiled media.

The independent judge reopens both saved histories and receipts, checks exact
editable snapshots and content-pinned manifests, decodes every video frame and
audio sample, and checks clocks, stream formats, unchanged source bytes, explicit
relinking, undo and retry. Harness observations bind the actual consumer traffic
and initially delivered bytes. Use only the supplied local tools and owned
workspace. All fifteen original checks remain required in the model arm.
Synthetic clients/references do not count as model trials.

In the baseline arm, Inkbolt is unavailable. Use file writing and the pinned
Python imaging/SVG tools for artwork. The same pinned Cutbolt consumer is
available through the bridge solely for compiling and rendering this task's
required linked video. Preserve the same source, edit, frames, preview, original
and revised timelines, color, alpha and clocks. Engine-only history, typed
handoff, undo and receipt checks are explicitly not applicable; do not claim
those guarantees from loose files. No Inkbolt call is permitted, even for judging.

For baseline before.json, use this exact editable-layer structure, filling
source.sha256 with the SHA-256 of original.rgba. after.json changes only the first
offset to [4,0]. review.json contains base_sha256 (before.json bytes),
action {"frame":"art","translate":[4,0]}, and proposed_sha256 (after.json bytes).

```json
{"schema_version":1,"width":32,"height":16,"color_space":"srgb","alpha":"straight","source":{"file":"original.rgba","sha256":"SOURCE_HASH"},"selected":"art","plays":0,"frames":[{"id":"art","source_index":0,"offset":[0,0],"hold":{"num":3,"den":25}},{"id":"other","source_index":1,"offset":[0,0],"hold":{"num":2,"den":25}}]}
```

Each baseline delivery-N directory contains source.json (its exact editable
layer structure), frame-0.png, frame-1.png, scene.json and compiled.mkv. Frame PNGs
must retain the exact straight RGBA samples at 32 by 16, with the first frame
shifted only in delivery-1. The scene uses encoded-sRGB straight alpha, the same
two holds, strict timing, loop ending, 25 fps and 2/5-second duration. Author it
as ordinary Cutbolt scene JSON, inspect it, and compile through the consumer
bridge. Each delivery-N-handoff.json is a baseline file inventory with exactly
schema_version:1, source, scene, frames, duration:{"num":2,"den":5}, and
frame_rate:{"num":25,"den":1}. source and scene are file identities containing
path, bytes and sha256. Each frames entry contains hold and image (a file identity).
Paths are filenames within that delivery directory. These file inventories are
not Inkbolt typed handoff receipts.

Write timeline-before.json and timeline-after.json as ordinary consumer project
snapshots with relative, content-bound compiled assets and the same two overlay
clips described above. Render them through the consumer bridge to original.mkv
and revised.mkv. No saved consumer session or undone output is required for the
baseline's artifact-only score. Preserve all compiled and source delivery files.
The judge reconstructs the edit with pinned Pillow and independently decodes the
compiled animations and timelines. Both arms retain the same seven artifact
checks; all baseline engine checks are reported as not applicable.
