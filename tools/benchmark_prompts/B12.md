# B12: Generate a family of layout variants (prompt version 1)

Keep this prompt, original.ttf, font-license.txt, green.png, orange.png and
renderer.ttf unchanged. Build one editable shared component with a blue
RGBA (20,80,150,255) size-20 original.ttf label A at (2,0), in a 44 by 24
nonwrapping frame, plus a 4 by 4 placed green.png image at (2,16). Place one
instance at local (0,0) on each artboard of a transparent 96 by 96 vector sheet:

| Name | Sheet position | Size |
| --- | --- | --- |
| wide | (0,0) | 48 by 24 |
| square | (56,0) | 32 by 32 |
| tall | (0,40) | 24 by 48 |

Use identity transforms apart from these translations and default remaining
properties. Define typed bindings with keys label (text), place (image position),
and image (image resource). Retain these datasets and their inheritance:

| Dataset | Parent | Text | Image position | Image |
| --- | --- | --- | --- | --- |
| wide | none | AAA | (36,16) | green.png |
| square | wide | AA | (24,24) | orange.png |
| tall | none | A | (10,38) | green.png |

Select wide, square and tall in that order. Export and review only each matching
artboard as wide.png, square.png and tall.png, at its native dimensions with
transparent background. Record each PNG's SHA-256 in outputs.json immediately
after delivery: exactly the keys wide, square and tall. Restore the base A/green
at (2,16), keeping definitions, resources, instances and all previous outputs.
Do not flatten the editable text, image or shared component. Write new files.

With Inkbolt, use the original unnamed font, retaining its license. The artboard
IDs and dataset/binding keys above are fixed; choose your own other IDs. Save
base.json after defining variants, source-wide.json, source-square.json and
source-tall.json at their selections, and restored.json after restoring the base.
Publish each PNG with a durable publication receipt. Verify the session history.
Deliver session.json with exactly session_id, revisions (base, wide, square, tall,
restored mapped to saved revision numbers in increasing order), and publications
(wide, square, tall mapped to your chosen publication request IDs). The restored
snapshot must be the current head. Arbitrary extra editing steps are permitted
if these saved states retain exactly the requested controls and resources.

For the no-engine baseline, use editable SVG and the pinned tools. renderer.ttf
adds the family name Inkbolt Variant Fixture to the original font, with identical
glyphs and metrics. It is supplied solely for SVG font selection; disable system
fonts. Use one 96 by 96 root SVG with a defs/g id="shared", containing a text
element and then an image. Text uses x=2, y=16 (the original font's baseline),
font-family="Inkbolt Variant Fixture", font-size=20, fill="#145096". Image uses
the selected x/y, width=4, height=4 and an xlink:href data:image/png;base64 URI
containing the exact supplied PNG. Follow defs with three nested SVG artboards
using the table's IDs, x/y, width/height, each containing one use with
xlink:href="#shared". Numeric matching viewBoxes and hidden overflow are allowed;
other attributes, elements, transforms, styles, external paths or resources are
outside this bounded contract. Preserve logical editable text, not glyph paths.

Deliver base.svg with A and green at (2,16), and wide.svg, square.svg, tall.svg
with their corresponding selections across the shared component. Render each
selected artboard to its matching PNG. Restore the exact original base.svg bytes
as editable.svg. Retain variants.json with this editable data:

```json
{"base":{"text":"A","position":[2,16],"image":"green.png"},"selected":null,
 "datasets":{
  "wide":{"values":{"text":"AAA","position":[36,16],"image":"green.png"}},
  "square":{"parent":"wide","values":{"text":"AA","position":[24,24],"image":"orange.png"}},
  "tall":{"values":{"text":"A","position":[10,38],"image":"green.png"}}}}
```

The baseline judge independently renders each selected viewport and checks it
and the delivered PNG against the same exact geometry as Inkbolt. Typed engine
bindings and session integrity are separate engine-only checks; retained base,
resources, output identities and all three pixel checks still apply. Delivery
hashes record identity, not an authenticated attestation of filesystem history.
