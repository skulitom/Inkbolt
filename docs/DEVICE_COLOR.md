# Explicit device colour conversion

`color.convert` connects bounded colour samples through retained ICC profiles. It is available through the Rust library, JSON CLI and MCP stdio. It does not edit a document. The complete registered extended vector colour criterion is independently verified: **160/167 (95.81%)** overall. See [the implementation registry](IMPLEMENTATION.md).

```json
{"command":"color.convert","source":{"space":"rgb","untagged":"assume_srgb"},"destination":{"space":"lab"},"values":[[0.2,0.4,0.8]],"intent":"relative_colorimetric"}
```

Device RGB, grayscale and CMYK use three, one and four normalized components respectively. Physical D50 Lab uses L in 0..100 and a/b in -128..127. Device endpoints require a matching `profile` using the existing embedded ICC or RGB builtin profile value. Untagged RGB may explicitly select `assume_srgb`; no printing condition or grayscale curve is guessed. Lab has its own D50 interpretation and rejects an unrelated device profile.

The original converter evaluates bounded classic and modern one-, three- and four-input lookup tables with continuous tensor interpolation. Matrix/TRC RGB and XYZ/Lab grayscale curve models are also supported. Inverse curves must be nonconstant and monotone; plateau endpoints follow [ICC.1 Annex F](https://www.color.org/specifications/ICC.1-2022-05.pdf). Native Lab coordinates stay in Lab between compatible stages so a redundant nonlinear round trip cannot shift a plateau decision. Output matrix conditioning, profile framing, table sizes and component ranges are checked before returning results.

Perceptual, colourimetric and saturation requests select the corresponding directional profile table and the declared default fallback. Absolute colourimetric conversion additionally applies source/destination media-white scaling. Matrix and gray-curve models provide their colourimetric fallback. Receipts name the selected tables, exact profile hashes, PCS values and clipped components. No optional black-point compensation or invented perceptual gamut mapping is performed. ICC v4 table connections use the reference-medium domain; connections to ordinary matrix/gray/Lab colourimetric values use the white-preserving affine bridge in ICC.1 section 6.3.4.3 and its inverse. Receipts expose the exact scale, offset and model. When either endpoint is v2, the explicit policy is direct PCS without guessed legacy black normalization. Other CMMs can choose legacy black normalization, so v2 perceptual/saturation cross-consumer identity is not promised. Native and flattened print separation accept all four intents.

Clipping diagnostics describe device-matrix or PCS-encoding limits, not a proof of device gamut membership. Optional `gamut:"off"`, `"if_available"` or `"required"` evaluates the destination profile's supplied gamut table. A separate colourimetric connection supplies destination-relative PCS coordinates; absolute conversion applies media-white scaling exactly once, while perceptual/saturation requests use relative-colourimetric diagnostic coordinates. The receipt names the diagnostic intent and selected tables separately from the conversion intent. Missing gamut data remains unavailable (or fails when required), and coordinates outside the table encoding remain unclassified. RGB, gray and CMYK profile classes retain their explicit endpoint policy; physical Lab has no implicit device gamut. Original samples and embedded profile bytes remain unchanged. Up to 4096 samples are accepted, with bounded profile storage and cancellation checks. Floating PCS override tags, unrelated profile classes/spaces, noninvertible destination curves and unsupported table semantics fail explicitly.

Named colours may now use a `device` declaration with an `encoding` endpoint, exact `components` and a retained `intent`. This applies to both process definitions and spot alternates. Existing `srgb`, encoded-neutral `gray`, `cmyk` and `lab` declarations keep their original interpretation. Display evaluation converts an independent copy to encoded sRGB. Named tints of managed colours interpolate the original device components toward device white before conversion; ordinary legacy declarations retain their earlier display-tint rule.

```json
{"op":"swatch_profile","id":"ink","action":{"type":"assign","encoding":{"space":"rgb","untagged":"assume_srgb"}}}
```

`swatch_profile` assignment preserves authored numbers and changes their declared interpretation. `convert` instead accepts a `destination` endpoint and changes numbers through the selected profile connection. It refuses untagged CMYK conversion until a profile is assigned. Legacy encoded-neutral gray converts as sRGB; assignment retains its one authored component and therefore requires a compatible one-channel endpoint. Tint aliases stay attached to their base, spot identities remain distinct, locked dependents protect edits, and receipts and durable session undo retain the original declaration. Conversion to a stored declaration must satisfy that declaration's component bounds.

Native ink PDF delivery embeds exact, deduplicated ICC bytes in ICCBased colour spaces and records each managed paint's rendering intent in its graphics state. Physical D50 Lab uses a calibrated Lab space. Spot alternates retain the profile and their source-component tint function. Managed paint explicitly disables optional black-point compensation with the PDF 2.0 control; the header and receipt declare the version. See [PDF.md](PDF.md) for calibrated page/group blending through `document.output_profile`, explicit sRGB default source spaces and legacy consumer limitations. Profiled process overprint in PDF is explicitly rejected; use an explicitly prepared native process delivery. Ordinary SVG/display PDF requires explicit `swatch_bake`, with the palette retained in the source document. The PDF colour-space contract follows the [public PDF specification corrections](https://pdf-issues.pdfa.org/32000-2-2020/clause08.html).

Native plate preparation connects each profiled source paint to the supplied print profile using the export's intent, without guessing an untagged printing condition. This includes source-component tints and spot alternate conversion. All four separation intents use the declared profile table and PCS-domain contract. Physical proof/gamut observation stays colourimetric, independently of the separation intent. Source declarations and profile bytes remain unchanged during evaluation and delivery.

`tests/test_device_color_cli.py` independently checks rational matrix/tensor equations, curve inverses, intent selection, white scaling, profile identities, policies, bounds and the shared agent command. `tests/test_swatch_profiles_cli.py` checks retained edits, source tints, exact embedded PDF bytes and operands, independent native ink equations, locks, transfer and durable restart/undo/redo. `tests/test_device_intents_cli.py`, `test_device_gamut_cli.py` and `test_pdf_profiles_cli.py` cover reference-medium equations, supplied gamut membership, calibrated PDF embedding, all four separation intents, native source precision and adjustment observation. The existing document colour policy is explicit: source encodings and per-definition intent (relative by default), one retained RGB output association for display delivery, or an explicit print profile and separation intent. There is no implicit global profile assignment to untagged CMYK. All mandatory regression gates and independent colour-engine, PDF-consumer and agent-interface checks passed before this checkpoint received credit. The evidence distinguishes supported contracts from the consumer-dependent behavior below.

Continuous tensor interpolation is an explicit engine policy. Sparse nonlinear ICC tables can produce large differences in other CMMs using simplex interpolation; densifying a profile can reduce this difference, but no universal error bound is claimed. Independent affine/dense fixtures test encoding and delivery separately from interpolation, while original nonlinear fixtures test the declared tensor equations. Exact source profile retention remains independent of consumer appearance.
