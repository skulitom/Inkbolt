# Logical vector canvases

`vector_canvas` is a document edit operation available through the library, JSON CLI and durable MCP sessions. It retains a logical viewport independently of the integer preview grid. Existing documents without the optional declaration keep their zero-origin integer canvas.

```json
{"op":"vector_canvas","action":{"type":"set","origin":[-2.25,1.5],"size":[5.25,3.5],"unit":"px","process_space":"rgb"}}
```

`set` accepts origin and size in the declared unit: px, pt, pc, mm, cm or in. Physical units use the document resolution. Conversion treats each input binary64 value and the physical unit factor as exact rationals, then rounds once to binary64. Saved `origin_px` and `size_px` are canonical logical pixels. Each size must be within 0.000001..32768; origin and far edges must remain within the existing coordinate limits. The document's integer width/height must equal the ceiling of its logical size. Invalid declarations and failed edits leave the source unchanged.

`{"type":"unit","unit":"mm"}` changes the display preference without recalculating the saved geometry, viewport or paint declarations. Inspection reports both canonical and selected-unit values. `{"type":"clear"}` explicitly returns to the existing integer viewport at origin zero. It preserves artwork and the current integer dimensions. A vector canvas requires a vector document with the existing encoded working buffer; assigning a CMYK process intent does not create an undocumented CMYK display buffer.

Artwork remains in world coordinates. Rendering evaluates a translated copy; original paths, transforms, masks, resources and retained snapshots remain editable. Canvas alignment uses the logical bounds. Explicit appearance-bake regions have their own viewport. Retained objects keep their original source canvas and use the existing pixel-grid placement contract for their bounded previews.

Preview dimensions are `ceil(logical_size * scale)`. The `none` sampling mode tests pixel centres against the viewport. Coverage and supersampling apply rectangular cell coverage at the fractional edge before the final associated-sample average. This is a bounded sampled preview, subject to the existing geometry/compositing precision; it does not claim exact analytic intersections of every artwork shape and viewport edge. Explicit uncropped padding exposes the surrounding evaluation region. Render receipts identify the world origin, logical size, evaluation grid and delivered dimensions.

Frames and artboards optionally retain `logical_size:[width,height]`, with matching ceiling width/height. Their clips, guides and exported physical boxes use the logical size. Artboard extraction adds the declared integer bleed to that size and inherits the document's unit and process intent. Placement and ancestor transforms retain the existing artboard export rules. Ranged exports retain selection order.

SVG writes the exact logical viewBox, including its origin, and physical dimensions in the chosen unit. CSS pixels use 96 pixels/inch, so px output dimensions account for the document resolution. SVG import accepts fractional viewport dimensions; its existing viewBox mapping becomes an editable root transform, with original source bytes and their hash retained by the import contract. PDF uses fractional physical page boxes and translates only its evaluation copy. Metadata and provenance refer to the original selected source viewport. Flattened print images keep their declared pixel pitch and clip to the physical page instead of stretching ceiling pixels across it; their partial edge samples retain the declared raster coverage and quantization.

`process_space` declares RGB or CMYK page intent. Typed RGB, CMYK, Lab, grayscale and named-ink paint records remain unchanged when that intent or a unit changes. CMYK canvases reject ordinary display SVG/PDF and RGB-preview print conversion with `COLOR_POLICY_REQUIRED`. Use explicit native vector ink delivery or profile-managed native prepress; native CMYK operands retain their values. Paints requiring a display alternate still require that explicit alternate for RGB previews. This checkpoint does not claim complete document colour management: rendering intents, untagged policy, gamut diagnostics and embedded-profile requirements remain tracked by the separate colour checkpoint.

Snapshots, semantic diffs, session undo/redo/retry and create-only publication preserve the declaration. Resource limits, profile requirements, output losses and unsupported semantics remain explicit. The independent unit, pixel-cell, physical-page, native-ink, source-identity and agent-history checks are in `tests/test_vector_canvas_cli.py`.

Saved scalar channels remain indexed from the preview's top-left pixel, independently of world origin. Named-ink recipe delivery samples those retained densities on the requested ceiling grid, preserves pixel pitch, and uses the fractional physical page. Its values represent ink density and do not acquire a second artwork-coverage mask. Changing canvas storage dimensions with incompatible saved channels fails existing validation instead of silently resizing those sources.
