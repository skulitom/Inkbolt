# Recovery contracts and acceptance

The Windows recovery implementation for readiness gate **A4** has a complete contract and workflow audit. This page maps its requirements to executable evidence and states the distinct contracts of every persistent command family. Acceptance requires the full repository checks on the same source state; an earlier result becomes stale after relevant code, storage or dependency changes. Exact build identities, logs and generated artifacts stay in the external evidence root.

The original 167 engine checkpoints remain unchanged. This audit supplies recovery evidence, while actual model-driven trials, practical-scale latency/memory gates, release validation and the rest of the readiness plan remain separate requirements. The accepted environment is a trusted local Windows filesystem with locking and hard links. Process interruption is tested; failing hardware, sudden power loss, hostile path replacement, remote filesystems and other platforms are not certified.

The comprehensive workflow uses original synthetic artwork, pixels and a generated font; it preserves all original input media and retains moved history/output files.

## Persistent command inventory

The source audit follows filesystem publication, SQLite mutation, process ownership and their public call sites. Commands returning inline snapshots or encoded artifacts do not persist those results until a caller saves them or invokes a publisher. Ordinary read operations may recover their own SQLite rollback journals without adding a logical editing revision.

| Commands | Commit and retry contract |
| --- | --- |
| `session.create`, `session.continue` | Publish a complete new session containing its initial durable request receipt. Same-ID retries return that result; existing unrelated sessions remain intact. Continuation records parent provenance and never edits the parent. |
| `session.apply`, `session.apply_proposal` | Commit state, history and request receipt together. Lost-response retries return the original revision/receipt even after the head advances. Stale new actions reject. |
| `document.publish`, `session.publish` | Create a complete final output once. Optional `receipt` enables historical retry/recovery; calls without it keep their explicit `OUTPUT_EXISTS` contract. |
| `session.backup`, `session.recover`, `session.migrate` | Create a verified copy at a new destination. Optional `receipt` uses the publication ledger. A restored session can acquire newer edits; replay never rolls them back. |
| `publication.recover` | Explicitly finish a prepared publication from retained evidence or return historical completion. Inspection with `publication.receipt` cannot publish. |
| `job.start`, `job.cancel`, `job.resume` | Persist admission/cancellation/attempt state, launch owned work and serialize its publication outcome. Inputs and output reservation remain bound to the job ID. A cancelled terminal job does not restart. |
| `job.status`, `job.wait`, `job.result` | May reconcile stopped ownership against durable evidence; cannot publish an absent staged output or restart a worker. `job.list` only reads saved state/membership. |
| `asset.import` | Publish or verify one content-addressed RGBA8 blob. An unchanged-source retry returns the same asset descriptor; `created` reports this invocation and becomes false when content already exists. |
| `font.import` | Publish/verify the retained license followed by the font blob. A failure between files may leave a complete license. Reimport verifies existing content and creates only the missing blob. |
| `sequence.import` | Publish/verify complete image-cache entries and return the complete editable document only when every frame succeeds. An interrupted or rejected import can leave complete cached entries. |

## Resource cache recovery

Cache imports do not create historical request receipts. After a lost response, repeat the import with the same original source files, interpretation and settings. Existing content must match its pinned identity; a corrupt blob is rejected and preserved. Importing unchanged sources reconstructs the same resource descriptors and sequence document, although per-invocation creation counts can differ. Keep the original inputs and save the returned editable document/session; cache filenames alone are not an imported-document or source-provenance archive.

Image and font imports are bounded synchronous operations. A pre-cancelled shared context rejects before starting. Once inside their bounded codec/file operation, a later context cancellation does not interrupt it or reverse committed content. Sequence import checks between frame/cache operations; cancellation can retain earlier complete blobs, and a cancellation after the final publication does not relabel the complete result as partial. Hard worker deadlines apply to the background export runner, not to every synchronous import call.

Publication writes an exclusively owned temporary and flushes it before creating the content-addressed final link. Normal completion/failure removes that invocation's temporary. Actual process death can leave unpublished temporary evidence. Retries preserve those orphans; they neither sweep the directory nor replace existing final files. Fonts retain their licenses, including the complete license from an interrupted pair. Existing source files and caller-owned destinations remain untouched.

## Revalidation and next work

Run `cargo fmt --check`, `cargo clippy --locked -- -D warnings`, `cargo test --locked`, `python tools/verify.py` and the repository material guards. The additional all-targets lint check includes the process fixtures. Acceptance records must identify the exact source, executable and candidate files tested and distinguish test-helper counts from workflow outcomes.

A4 is the current Windows recovery gate, not a claim that every command runs asynchronously or that the overall agent-readiness objective is complete. Storage changes for large documents must preserve and rerun these contracts. The next implementation work is A5's measured baseline and practical storage/rendering scale, alongside the remaining original checkpoint scope; A1 model trials and the final audits remain open.
