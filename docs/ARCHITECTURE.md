# Architecture

`jobs` connects bounded checksummed SQLite input/state/runtime tables to hidden local supervisors and contained export processes. Launch/worker leases close the idle-exit admission race; recorded generations and PID/creation identities distinguish live owners from interrupted work. Immutable document inputs are separate from progress. A publication permit holds the job writer transaction across create-only publication and result recording, serializing cancellation with the commit point. Stopped-worker reconciliation only recognizes already-published evidence; it does not create absent outputs. See [durable jobs](JOBS.md).

`jobs::listing` reads a bounded admission inventory and only the requested input/state payloads in one SQLite snapshot. Cursors bind the original input membership and queue root/build, keeping traversal stable as progress changes and excluding later admissions until a fresh listing. Byte limits can shorten a page. Discovery neither opens source resources/executables nor reconciles outcomes or starts workers.

`job_process` supplies Windows process containment for durable export runners: pinned executable bytes held against replacement, a cooperating stdin startup gate, an owned job object with one-process and committed-memory limits, an independent deadline watchdog, PID/creation-time inspection and persistent OS file leases. Actual child/supervisor crash tests cover both sides of assignment. Stop requests remain distinct from output outcomes. This Rust library also underpins the durable export queue. See [job processes](JOB_PROCESSES.md).

`publications` adds optional durable receipts to existing document/session publishers. Encoding precedes ledger locks; flushed staging bytes and their Windows file identity are committed before create-only publication. Prepared recovery verifies the retained staging link and recognizes only the same physical file at the destination. Checksummed bounded SQLite records preserve original results; failed completion writes return explicit pending-completion success. Workspace checks apply before following stored output paths. See [publication receipts](PUBLICATION_RECEIPTS.md).

`sessions::lineage` adds storage version 2 while retaining version-1 read/write support. Explicit migration adds only an empty provenance table to a checked copy; existing rows and logical history identity remain unchanged. Continuation verifies a pinned parent backup, captures an exact revision and atomically creates a new session with its checked origin and initial retry receipt. Session reads validate the local link without traversing external backups. Creation prepares its response before publication, and the shared executor preserves successful backup/recovery/migration/continuation under late cancellation. See [migration and continuation](SESSION_LINEAGE.md).

`sessions::backup` pins the expected head in a read transaction and uses bounded steps of the external SQLite backup API. The prepared copy must pass the same complete history verifier and match the captured logical fingerprint before create-only publication. Recovery streams exact hash-pinned bytes to its own temporary, validates the copied history and publishes without modifying the input. Source resource bindings remain data until explicitly rebound. Shared verification now checks previous-state linkage, snapshot revision/state linkage and actual stored payload lengths. See [checked backups](SESSION_BACKUPS.md).

`visual_diff` reuses complete previews in a common sRGB view, restoring original source identities and retaining original output-profile declarations. It aligns compatible world/artboard-local grids, fills absent extents transparently, crops before allocating the bounded common images, and records exact and thresholded changes with per-side world maps. It performs no registration or resampling. Session comparisons share one read-only pair capture and release the database before rendering. Legacy numerical differences retain their positional contract while sharing controlled validation/rendering. See [visual comparisons](VISUAL_COMPARISONS.md).

Receipt construction precedes file publication; the existing atomic hard-link commit point and late-cancellation semantics remain. See [document checks](DOCUMENT_CHECKS.md).

See [focused previews](FOCUSED_PREVIEWS.md); neither path claims incremental render evaluation.

## Implemented editing core

The Rust library owns typed requests, document invariants and capability reporting. The CLI is a bounded JSON transport over files or stdin, with correctly rounded f64 parsing for numeric round trips. Schema-v2 snapshots carry IDs, dimensions, resolution, revision, optional image and font dictionaries and explicit sRGB interpretation. Items use flat storage with optional parent IDs; sibling order runs bottom to top. Vector items carry geometry and appearance; pixel items carry bounded inline straight RGBA8 data. Groups, named layers, frames and artboards own child relationships. Schema-v1 empty snapshots remain readable and promote to v2 on edit. No external application is required.

`model` validates snapshots and resource bounds. `geometry` performs original f64 affine and analytic curve calculations. `edit` validates a private candidate after every operation and publishes a new snapshot only after the entire batch succeeds. For snapshot edits, expected revision checks the supplied document. Session commands check the committed head inside a transaction and deduplicate persistent request receipts. IDs are caller-supplied and unique within a document; names may repeat.

`primitives` expands editable rounded rectangles, polygons, regular polygons and stars into bounded line/cubic commands shared by rendering, clipping, analytic bounds and SVG. Requested corner radii persist; proportional normalization and quarter-cubic geometry define their evaluated outline. `paths` performs selected anchor/handle edits in local or world coordinates, exact de Casteljau splitting up to f64 roundoff, seam-preserving closed-contour reversal and explicit coincident/bridged joins. Conversion of an analytic ellipse is a disclosed four-cubic approximation. `simplify` proposes bounded line/cubic reductions and independently certifies their encoded values with exact rational Bernstein deviation bounds and swept-hull topology checks. Unprovable spans remain unchanged with reported reasons. See SIMPLIFICATION.md. See PATHS.md for degeneracies, limits and topology behavior.

`work_paths` stores nonprinting geometry as ordinary items in either document kind. Existing path edits, discovery, hierarchy and persistence share the vector geometry contracts. Original f64 selection coverage splits cubics into y-monotone intervals, finds scanline roots by bounded bisection and integrates horizontal spans across 256 subrows. Geometry-only region reads ignore appearance and do not change their sources. Vector-mask copies retain current world placement through an independently editable item-local clip. Nonprinting items do not interrupt clipped adjustment chains. See WORK_PATHS.md for numerical limits and copied-state semantics.

`query` filters items by content/shape type, inherited visibility, locks and inclusive world geometry bounds. It can return revision-scoped path anchors and cubic handles in local/world coordinates. Default discovery excludes items whose own, ancestor or affected descendant locks would block editing. Bounds are unclipped and exclude strokes; this is not a painted-area hit test. Discovery is read-only, and topology changes require rediscovering command indices. The CLI and MCP expose this same query contract.

`scene` validates hierarchy, composes world transforms, propagates visibility/locks and calculates unclipped descendant geometry bounds. Cycles, missing parents and excessive depth fail before recursive work. `layout` aligns/distributes world bounds and converts movement back into each parent's coordinate system. Structural edits preserve IDs and explicitly reject ambiguous selections or appearance-losing ungroup operations. Empty groups have null bounds.

## Durable sessions

`sessions` persists original schema-v2 documents, explicit resource bindings, named snapshot references and request receipts in a versioned SQLite database. Immutable content states store document revision zero; session revisions increase monotonically for every committed action, including undo and snapshot metadata changes. An edit batch produces one undo point. Content hashes cover stored bytes; metadata and receipt hashes detect corruption, including changed retry fingerprints. They are checksums, not authentication.

Mutations use immediate transactions, rollback journal DELETE mode and synchronous FULL. The committed head, stacks, new content and receipt change together. Reads use consistent transactions; reopening a hot journal uses SQLite recovery. A test-only child-process harness forces dirty-page spill, then terminates the owned writer before or after commit. Independent tests open each action in a fresh CLI process and inspect SQLite bytes through Python's separate library.

Creation initializes and flushes a private temporary database, closes it, then publishes a create-only hard link to the session-ID-derived filename. Existing sessions are never replaced. Failed initialization may leave an unpublished temporary after process termination; only files owned by the current creation attempt are cleaned automatically. History storage and request counts have explicit caps and no silent eviction.

`control` supplies an atomic cancellation token, optional caller-owned marker and deadline. Checks occur between edit operations and immediately before session commit/publication. Cancellation before commit rolls back the complete transaction. After commit, cancellation cannot relabel the action as uncommitted; retrying the same request ID retrieves its original receipt. Blocking filesystem/SQLite calls are not forcefully interrupted. Rendering and exports currently remain separate bounded snapshot operations.

See [SESSIONS.md](SESSIONS.md) for exact bounds, failure recovery, resource persistence boundaries and backup requirements. Resource files stay in their existing immutable external stores; sessions do not package fonts/images or touch original import sources. No listener, service or account is added.
