- `inkbolt_schema_lookup` with `name: "index"` returns `commands` (every engine command, including `document.publish`, `document.preview`, `svg.import`, `font.import`, `session.create`, `session.apply`, `session.publish`) and `types` (`document`, `operation`, `action`, `item`, `content`, `geometry`, `paint`, `resources`). - `inkbolt_run` takes `{command, arguments}`, where `arguments` are the command's fields without `command`. An unknown field or a missing required one gets `INVALID_REQUEST` with the field name and `details.schema_lookup`.
- `inkbolt_document_create` with `id`, `kind` (`vector` or `raster`), `width` and `height` returns a snapshot: `{"color_space":"srgb","height":H,"id":ID,"items":[],"kind":KIND,"resolution_ppi":96.0,"revision":0,"schema_version":2,"width":W}`. It writes no file.
- `inkbolt_document_edit` takes `document` (the latest snapshot), `expected_revision` and 1 to 64 `operations`. If `expected_revision` differs from the snapshot's `revision`, it fails with `REVISION_CONFLICT`, "Expected revision does not match the supplied snapshot". On success it returns `result.document` at revision + 1 and `result.changes`. An `add_svg` operation (`{"op":"add_svg","prefix":P,"svg":"<svg fragment>"}`) returns `item_ids` mapping each SVG element to an editable item `P-svg-N`, and `losses` noting that rounded corners and arcs become editable cubic curves and colours are quantized to RGBA8. Snapshots list every item in `document.items`; the SVG root is a `group` item and each shape is a vector item whose `content` is `{"type":"vector","fill":[R,G,B,A],"fill_rule":...,"geometry":{...},"stroke":...}`, with colours as RGBA8 arrays (`#1E66F5` is `[30,102,245,255]`). A `vector` operation (`id`, `geometry`, and optional `fill`, `stroke`, `fill_rule`) replaces that item's whole vector content: an omitted `fill` or `stroke` becomes none and an omitted `fill_rule` becomes `nonzero`, so recolouring means sending the item's current content back with only the colour changed. `properties` only takes `id`, `name`, `visible`, `locked`, `opacity`, `fill_opacity`, `blend` and `coverage`: a `properties` or `fill` operation carrying a colour fails with `INVALID_REQUEST`, "Arguments must match the command schema; use details.schema_lookup", with `details.schema_lookup` naming `document.edit`. Text needs two steps: a `font_put` operation (`{"op":"font_put","id":FONT_ID,"font":<the import's descriptor>}`) that adds the font to the document, and, on the `add_svg` operation itself, `font_bindings: [{"family":...,"font_id":FONT_ID}]` (optional `weight`, `style`) mapping the CSS `font-family` used in the SVG to it. `<text>` without a matching binding fails with `SVG_FONT_NOT_BOUND`, "No explicit font binding matches the requested family, weight and style", with the element's line and column, even when the font is already in the document. Edits never write files.
